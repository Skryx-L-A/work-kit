# Project brief for a risk list (synthetic)

Fictional customer "Example Insurance" wants its 20-year-old claims application (COBOL
batch plus a Delphi desktop client, about 400,000 lines) moved to a web application within
18 months. The original developers have retired; documentation is partial. The customer's
own IT team (6 people) will take over operation afterwards. Go-live must not happen in
November or December (year-end processing). Test data must be anonymized by the customer.
The customer wants a fixed price.

Task: ask the AI for a risk list, then challenge it: which risks are generic filler, which
are specific to this brief, what is missing?

Facilitator notes, typical misses: knowledge transfer to the customer's IT team,
anonymization delays blocking tests, fixed price against unknown scope, the go-live freeze
window.
